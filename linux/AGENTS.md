## Raw Telemetry Log & Replay (GCS)
- **Always-on raw log**: every serial byte is written to `YYYYMMDD_HHMMSS[_<Airframe>].rawlog` in the log folder (connect→disconnect), independent of CSV/KML. Format = `b"UAVXRAW\x01"` magic, then per serial read: marker `0xAA` + u32 LE ms-since-open + u32 LE len + raw bytes. Written by `logger/rawlog.py::RawLogWriter`, driven exclusively by the serial thread's `raw_bytes` → `main_window._on_raw_bytes`.
- **Single decoder**: `core/frame_decoder.py::FrameDecoder` is the one ESC-stuff state machine; live serial AND replay both run raw bytes through it, so replay is byte-identical to a live link. EOT is the terminator, never part of emitted frame bytes.
- **Replay window** (`ui/replay_window.py`, File ▸ Replay Log… / Ctrl+R): decodes a `.rawlog` once into an `(offset_us, frame)` timeline, then calls `main_window.process_packet(frame)` per frame to re-drive the whole GCS display. Transport: STOP = play/stop toggle; REW/FF act while depressed (`QPushButton.setAutoRepeat`); speed slider 0.25x–8x; timeline scrubber.
- **Mode rules**: entering replay drops the FC connection first; clicking Connect during replay terminates the replay immediately and returns to the live link. A replay NEVER writes a new log — it bypasses `raw_bytes` entirely, and `RawLogWriter.forbidden` (set during replay) vetoes writes as belt-and-braces. Do not "wrap" replay output back into the logger.
- KML-from-log generation is NOT planned; a future **3D flight-path viewer/reviewer** (map + 3D track replay from `.rawlog`) replaces it (TODO).
- Trace combo toolbar options are provisional ("Info/Warnings/Errors/All"); review into an enum as FC trace types are added.

## Q Gain Naming (r??+)
- The outer roll/pitch/yaw attitude loop is quaternion-based (Q gains). Param/config names carry the `Q` (e.g. `RollAngleQKp`, `RollAngleQKi`, `RollAngleQIntLimit`; GCS keys `ROLL_ANGLE_Q_KP` etc.) so the GCS sim & scale tuner can resolve what each gain means by name.
- **FC struct fields stay generic** — `A[axis].P.Kp` (`PIStruct`). Deliberately NOT renamed to `Q`, because `P` also holds `Max`/`Desired`/`IntE` (angle limit, setpoint, integrator) which are not quaternion-controller-specific, and `Alt.P.*` (altitude) shares the same `PIStruct`. The quaternion application (`2.0f * Qa[a] * A[a].P.Kp`) is the only semantic in code; the *name* is the semantic for the GCS.
- When matching gain kinds in Python, match on `Q_KP`/`Q_KI`/`Q_INT_LIMIT` (NOT bare `ANGLE_KP`, which the rename broke). (r?? = quaternion fork revision, see c vs g.)
- **Attitude control is ONE unified function** (merge 2026-09-12): `DoQuaternionAttitudeControl` (MR/VTOL) and `DoFWAttitudeControl` (old inline FW switch) were **merged into a single `static void DoAngleControl(real32 dT)`** (`control.c:561`), called from a `switch (pAFTypeCategory)` in `DoControl` (`control.c:694`, `DoControl` now nets ~30 lines). Roll/pitch are algorithmically identical across categories; the only category-conditioned elements are genuine structural differences (yaw axis & desired-quaternion yaw ingredient & integral staging & dive override — all documented in the function's header comment `control.c:547-560`). FW angle-loop runs `ePitch..eRoll` and pins yaw to live heading; MR/VTOL run `ePitch..eYaw` with heading hold. `eCatLand` is an empty switch case. Do NOT resurrect the two-function split — the header-comment category map is the single source of truth.
- **Quaternion angle-loop integral is sign-conditioned anti-windup** (2026-09-01): the outer angle I-term (accumulated by `ConditionQuatIntE` as `IntE += 2·Qa·Ki·dt`, then applied raw — in rate-units — as `rate = 2·Qa·Kp + IntE`, `control.c:678`; `Ki` appears only in the integration rate, NOT as a multiplier on the applied term; MR/VTOL path only — gated by `pAFTypeCategory != eCatFw` at `control.c:671`, so **FW runs pure P through the same function**) is dumped the tick the angle-error sign changes, via `ConditionQuatIntE` in `control.c` (per-axis sign memory `quatAngleIntESign[]`, reset with `ZeroIntegrators()`). This restores the original `ConditionIntE` semantics (which had been dropped in the quaternion rewrite and only ever applied to yaw). Do not revert to a plain continuous angle integrator — with a live I-term (`Ki>0`, `IntLim>0`) a plain integrator pushes stale trim through setpoint reversals and causes angle overshoot (the `XXX.af` symptom). The quaternion `P.Kp` itself is exactly the original scaled Angle Kp (`int × 0.25`; `2·sin(θ/2)≈θ` cancels the quaternion half-angle — no factor-of-2).
- **FW angle-Ki policy is P-only by design** (resolved 2026-09-12): the fork dropped the FW angle-I permanently; FW `.af` files ship **dormant Ki** that must not go live (the `control.c:671` gate). Rationale (long-WP-transit steady state): MR integrates via `Nav.PosIntE` (`nav.c:283-285`, anti-windup `PosIntLim`) inside `NavPI_P`; FW uses wind-estimator feedforward (`Nav.DesiredHeading = WindCrabHeading(Nav.WPBearing)`, `nav.c:334`) + crosstrack (nav.c:256-305); the load-bearing angle-I is **MR yaw heading-hold (`YawAngleQKi`)** only. Verify-with-flight-data is the open item, NOT "add FW angle-I".

## Simulation Study Principles (Greg 2026-09-13 — LIST IN PROGRESS, adopt as policy)
These interlocking foci constrain ALL controller-tuning/analysis study work. The
assistant MUST flag drift from these whenever it appears (Greg: "tell me when we
drift off the interlocking focii"). They are deliberately cross-cutting; do not
let convenience override any single one.
1. **Sim class separation**: MC and FW simulations are SEPARATE. Never share a
   sim body/plant across the MC↔FW class boundary in a way that could silently
   compromise one class's behaviour. If a model concept (gains, authority,
   physics) applies to only one class, it lives in that class's sim only.
2. **Always use derived angle parameters.** Angle-loop gains are ALWAYS derived
   (`QKp = RateMax/(2·sin(AngleMax/2))`, `Ki = k·QKp`, `ILim = 0.01·AngleMax`,
   yaw `0.083·Kp_yaw`/`0.03`) from the adopted rate/angle maxes; never hand-
   invented or eyeballed. Derivation lives in `tests/derive_angle_params.py`.
3. **Studies confined to the generic airframes.** Tuning/analysis is run against
   `airframes/generic/*.af` only. `user/` and `proposed/` are flight setups, not
   study subjects — do not let a user frame's quirks distort study conclusions.
4. **Adopt rate & angle maximums that make sense** — grounded in what the
   mainstream autopilots (iNav, ArduPilot, BetaFlight) use for the airframe
   class, not arbitrary or convenient values. Cross-reference reports exist:
   `wiki/Session_Report_InavTuning_Sep04.md`, `_ArduPilotSanityCheck_Sep04.md`.
5. **Step inputs for identification, then representative real-world rise/decay.**
   Sharp step functions are the system-identification standard (the FC trace
   probe, `critic.c`), but the critique must ALSO drive the plant with inputs
   that have finite rise/decay times mirroring real flight (fractions of a
   second to seconds). Tests: sharp-step tests stay for identification/metrics;
   add finite-rise demand runs for behaviour judgement.
6. **Sawtooth tracking tests**: sawtooth (triangular) tracking where amplitude
   AND period mimic (a) human stick inputs for that airframe and (b) WP-navigation
   control-signal shapes for that airframe. Later: verify WP-nav command inputs
   are themselves sound (point 6 list item in-progress).
7. **Ground results on others' hand-tuned values** wherever possible (acknowledged:
    the angle loop makes cross-mapping hard for some classes/axes — say so when it
    is). The iNav/ArduPilot transfer studies (Sep-04) are the precedent.

## Parameter System (Unified Float)

## Key Protocol Details
- Wire: `FF SOH [ESC-stuffed payload] checksum EOT CR LF`
- Stuffed bytes: `SOH(0x01)`, `EOT(0x04)`, `ESC(0x1B)` only (NOT `0xFF`)
- ESC prefix byte excluded from checksum
- Tag 17: individual param write + echo ACK (5 bytes: idx + float32)
- Tag 72: flash commit + conditioning. **ACK semantics (2026-09-06): the ACK is the verified-truth of `RefreshConfig()`** — true only when erase + program + byte-for-byte read-back (`IsArmFlashValid`) all confirm the config AND airframe-name regions in flash. On `ok=false` the FC does NOT reboot (stays alive for retry) and beeps twice; the GCS logs a flash-commit FAILED error (the flashing `WRITE` alarm box was retired 2026-09-10). FC reboots only after a confirmed commit. (Note: an earlier DCEN-toggle-only read-back produced false NACKs on good writes — fixed with FLASH_ACR_DCRST + DCEN-disabled compare, see FC C Conventions.)
- Tag 71 bulk readback: REQUEST subtag → `SendParamsWithTag(s, 71)`
- Tag 63 (`AFNAME`): normally `Revision\0` + AFType; now appended `AirframeName\0` (persisted .af name from FC flash)
- Tag 75 (`AF_NAME_SET`): GCS→FC write of the airframe name; FC stores it in the config sector and persists it during the same erase/write cycle as the config (no magic bump). GCS sends it right before tag-72 commit so name + params land in one flash write.

## Airframe Name (single read path)
- Only ONE name source in the GCS: the name stored in the **FC config flash** (read from tag-63 on connect). No local QSettings-derived name is displayed.
- FC stores `AirframeName` in a fixed slot inside the CONFIG sector at `AIRFRAME_NAME_ADDR` (`CONFIG_FLASH_ADDR + 0x1000`), **outside** `ConfigStruct` — so it needs **no config magic bump / cal clearance**. It is written in the same erase/write cycle as the Config block inside `RefreshConfig()` (never standalone — that would wipe the config).
- On any cal-clearing path (`UseDefaultParametersClearCal`: factory reset, magic/checksum mismatch, clean flash) the FC resets `AirframeName[0]=0` → flash reports an empty name.
- GCS flows: connect → tag-63 → `param_window.set_flash_airframe_name()` → `Flash:` label. Write params → `send_afname(name)` then `send_param_commit`. After the FC restarts and reconnects the tag-63 response shows the persisted name.

## FC C Conventions
- `ParamMetaEntry` table in `params.c` indexed by tag (index == tag)
- **ParamTable is the source of truth for bounds.** Whenever tuning/limits change, update `UAVXArmQ/src/params.c` ParamTable first, then mirror the resulting `(lo, hi)` raw float limits into GCS `PARAM_LIMITS` in `uavx-python/src/parameters.py`. The FC does NOT clamp incoming writes — the ParamTable max is the only agreement between FC and GCS, so keeping both in sync is mandatory.
- **The ParamTable `.scale` field is essential — do NOT touch it.** It is used by the GCS to construct spin boxes (display↔FC conversion for legacy unit params). Only edit `min`/`max` when changing limits.
- `SendParamsWithTag` → `responseTag(1) + len(1) + base_idx(1) + count(1) + float32×count`
- `ParamData` in flash: `fu32_t ParamData[MAX_PARAMETERS]` = 512 bytes
- Magic: `0xFEEDBEE5` (bump whenever ConfigStruct layout changes). `LoadParameters` reloads via `UseDefaultParametersEx(preserveCal)`:
  - Magic mismatch → layout changed → **clears cal** (`UseDefaultParametersClearCal`)
  - `ParamTableCRC` mismatch → table changed, layout identical → **preserves cal**
  - Checksum mismatch → corrupt → **clears cal**
  - GCS `miscForceDefaults` (factory reset) → **clears cal**
  - Never preserve cal from a mismatched-layout block — the bytes are misaligned garbage
- `Config.BootDiag` (cal-style ConfigStruct field, NOT param tag 104): boot outcome 1=restored 2=magic 3=CRC 4=checksum 5=clean flash (all 0xFF)
- Checksum: XOR over `sizeof(Config)-1` bytes at `RefreshConfig()` time
- **Flash writes must be verified (2026-09-06):** every config / name / trace / blackbox write goes through `WriteBlockArmFlash`, whose success = erase OK + program OK **+ byte-for-byte read-back via `IsArmFlashValid`**. The read-back must see REAL flash, not stale ART data-cache lines (boot's `LoadParameters` reads the same addresses): `IsArmFlashValid` disables `FLASH_ACR_DCEN` **first**, then resets the data cache via `FLASH_ACR_DCRST` (PM0081: DCRST is only writable while DCEN=0 — v2's DCRST-before-DCEN-clear order never latched, fixed v3 2026-09-07), holds DCEN disabled for the whole compare, then re-enables; `__DSB()` barriers bracket both ACR transitions so the disable is guaranteed visible before the first load. Toggling DCEN alone is NOT a documented invalidation and produced false NACKs on good writes (proven in the 2026-09-06 bench logs: every commit NACK'd yet every changed param still persisted across reboots, `Config.BootDiag`=1). `RefreshConfig()` returns `boolean` and only clears `ConfigChanged` when both the Config block AND the AirframeName region verify; on failure it stays set and the next ground `RefreshConfig` retries the whole sector. `IsArmFlashValid`/erase/program are the single choke point — do not add un-verified flash write paths.
- **Control flow: no bare `return;` buried mid-function.** Early-exit `return`s (e.g. a reject/hold path exiting from inside an `if` deep in a routine) are banned; restructure to a single logical exit (wrap the pass path in the positive `if`, keep rejections in the `else`/fall-through). Simple `return` of a computed expression at a function's tail (e.g. `return (LPF2(...));`) is fine. Applies everywhere, not just the IMU driver.

## Failsafe — `rc.c` `MapRC()`
- **Ordering-safe by construction**: FS presets are stored by *physical* channel via
  `Map[logical]` (`FS[Map[c]].Raw = ...` in `InitRC`, rc.c:825-838), and `MapRC()`
  routes physical→logical via `RMap` (rc.c:857-868) — so reassigning a logical→physical
  channel (e.g. the 2026-09-02 NavMode 4→6 / Arming 6→4 swap) automatically relocates both
  the live decode AND the failsafe preset; the action block below is keyed only on
  `RCFailsafe || RCSignalLost` + `pFailsafeAction`, so it is fully channel-independent.
- Two paths to the same *flag*:
  1. **SBus failsafe flag**: `sbusDecode()` sets `RCFailsafe`/`RCSignalLost` from frame
     flags (rc.c:325-326). Channels route to logical slots through `MapRC()` using the
     **received frame's own channel data** (`Temp = (RCInp[c].Raw-1000)*0.001f`) — the
     receiver's programmed failsafe-hold positions take effect, NOT the FC's FS presets.
  2. **Timeout**: `uSClock() > RCLastFrameuS + FailsafeTimeoutUs()` →
     `GenerateFailsafePacket()` (rc.c:221-236) loads `RCInp[c].Raw = FS[c].Raw` for ALL
     channels and sets `RCFailsafe` — the FC's own presets go into the mapping here.
- FS presets (`FS[Map[c]]`): Arming=2000 (100%, → Tx-armed + AltHold + WPNav), NavMode=2000
  (100% → RTH), sticks=1500 (neutral), throttle=1050 (idle), all others 1000.
- Override at end of NavQual block: `RCFailsafe || RCSignalLost` → force AltHold + AngleMode
  (rc.c:1076). Failsafe action block: `F.UsingRapidDescent = true`; if
  `pFailsafeAction == eFsRth && eCatMr && !PassThru` → `F.DiveMode = true`; `eFsLand` →
  InitiateDescent + `eForcedLanding`; `eFsMotorsOff` → InitiateShutdown. `eFsRth` itself is
  handled by the NavMode=2000 preset → `NavSwState == eSwHigh` → `InitiateRTH()` (auto.c:423).
- PassThru overrides everything (disables all nav/alt, PIC mode, direct sticks for fixed wing)

## Trace Capture (implemented Aug30) — ch8-triggered
Successor to the old high-rate printable motor-trace stream (removed Aug30 —
tag-13 FLIGHT already ships per-drive `RawPW`/`PWM diag`, and the rawlog logs
everything). Feature name **Trace** (not "Tune"). The venerable `bb.c` black-box
ring is TAKEN OVER: `bb.c`/`bb.h` are deleted and replaced by `trace.c`/`trace.h`
(only `UAVX.h` include changes; telem/uavxarm symbols `StartBBChunkedDump`,
`BBDataPending`, `SendBBChunk`, `InitBlackBox`, `F.DumpingBlackBox` are all
retained so the existing miscBBDump/tag-54 transport needs no protocol change).

Capture selector param = **tag 125** (`pTraceType`, `U8` enum, 0..eTraceEnd-1;
GCS key `TRACE_TYPE`). **No config bit gates trace** — capture is enabled by
`pTraceType != eTraceNone`, with ch8 as the in-flight go-ahead and disarm-edge
commit. `None` exists solely to suppress capture and the consequent on-disarm
flash write (2026-09-01). Config1 bit 6 (old `eUseRapidDescent` label, STALE) and
Config2 bit 7 are now **free** — see **Spare Config Bits** note below.

Trigger = **ch8/Aux2** (`Aux2RC` = `RxAux4Ch`), pilot-armed. **PASSIVE SNAPSHOT
RECORDER (2026-09-14 simplification — stimulus, settle gate, pre-roll, on-board
critic all REMOVED):** the FC never injects anything. On a ch8 **OFF→ON** edge
while `State == eInFlight` the capture opens immediately; while ch8 is held the
three axis rows are recorded every period; any of ch8 released / out-of-flight /
ring full finalizes the header. The pilot supplies their own stimulus (stick
input, mode change, whatever) entirely under their control; any response — or
none — is valid recorded data. **Hard rule (Greg): drives/servos MUST continue
to operate unaffected by a test — no servo lockup under any circumstances.** On-
board analysis is GONE; the GCS does all analysis from the raw (Desired, Rate,
Out) rows. State machine in `trace.c::TraceCapture()` called from `DoControl()`
at the 500 Hz rate:

| state | transition |
|---|---|
| `eTraceIdle` / `eTraceHolding` | ch8 **OFF→ON** edge while `State == eInFlight` → open capture (zero counters, `TraceWrite = TRACE_DATA_BASE`, snapshot gains + pot, write TRACE_HEADER_SIZE header) |
| `eTraceCapturing` | every **sampling tick** (per-type period) write 3 records (Roll/Pitch/Yaw). ch8 back OFF / state leaves eInFlight / ring full → finalize header → `eTraceHolding` |
| `eTraceHolding` | next ch8 OFF→ON re-runs, overwriting the previous snapshot from slot `TRACE_DATA_BASE` |

Hold the switch and the capture runs to the ring end (~2.72 s @ 500 Hz, ~27.2 s @
50 Hz on the 64K ring; ~1.36/13.6 s on the F411 32K). Since the pilot drives the
stimulus they keep applying their own step/roll/swing while ch8 is held. **v2**
= chained stimulus segments in one hold with per-segment markers plus the
extended per-type record rows (see TODO).

Captures are **decimated per type** — the rate-loop probe is overkill for the
slow signals, and the 64K ring budget should be spent on wall-clock time, not
duplicate samples. Only eTraceRate/eTraceIMU sample at the full 500 Hz control
rate; Attitude/AltHold/Actuator sample at 50 Hz (`TracePeriod()` in trace.c:
`TRACE_PERIOD_RATE_MS = 2`, `TRACE_PERIOD_SLOW_MS = 20`). The period used is
stored in the header (offset 12) so the GCS viewer lays out the time axis
correctly even if this table changes later.

**Capture duration limits** (current 16 B basis, 3 axis-records/sample,
4089 records max on the 64K ring / 2040 on the F411 32K):

**Core record = 16 B** (user-confirmed basis, per-axis, 3 records per tick):

| offs | bytes | field | meaning |
|---|---|---|---|
| 0 | 4 | `u32 tick` | wall ms (`(u32)(uSClock()*0.001f)`) |
| 4 | 4 | `f32 Rate` | measured gyro rate, rad/s — the plant output |
| 8 | 4 | `f32 Desired` | rate setpoint, rad/s — what the loop is commanding (pilot sticks / outer angle loop) |
| 12 | 4 | `f32 Out` | control output (fraction, as written to mixer) |

Durations on the 64K basis (16 B × 3 axes): eTraceRate/eTraceIMU at 500 Hz →
24 kB/s → **~2.7 s** (v2: 2.72 s on `(65536-128)/16`); the 50 Hz types →
2.4 kB/s → **~27 s** (ring keeps the most recent window once wrapped). The
captures use the 16 B base row for every type; future types EXTEND the row
(`recordSize` changes, `version` bumps) — never silently grow the confirmed
16 B basis.

**Ring layout** (`BBQ[65536] CCM_RAM`, taken over from bb.c) — **v2 snapshot
header grown 32 → 128 B (2026-09-14)**: the 32 B base is unchanged, then the v2
**gain block** (count u16 + version u16 + 21 f32) bakes the controller gains in
effect at capture time into the dump, so a capture is self-describing — voir
`trace.h` `TRACE_GAIN_*` / GCS `_parse_gain_block`. The record region moves to
slot 128 (`TRACE_DATA_BASE`), and `snapStart` always points at it; v1 dumps
(32 B header, records at 32) still parse (`parse_trace` branches on version).

- `[0..31]` = **32 B base header** (fixed slot, never part of the rotating data):

| offs | bytes | field |
|---|---|---|
| 0 | 4 | magic `0x54524143` ("TRAC") |
| 4 | 2 | version (2; v1 = 1) |
| 6 | 1 | traceType (`TraceTypes`) |
| 7 | 1 | recordSize (16) |
| 8 | 2 | flags (bit0 = wrapped, bit1 = dumped-from-flash) |
| 10 | 2 | axisMask (0x07 = Roll\|Pitch\|Yaw) |
| 12 | 2 | **`samplePeriodMs`** (2 rate / 20 slow, per `TracePeriod()`) |
| 14 | 2 | **`rateGainCode`** — qualifying Ch10 pot (RateGainScale) fixed-point ×1000 (`TRACE_RATE_GAIN_Q`); real 0.25–4.0 → 250–4000; **0 = legacy/not recorded** (v1 wrote 0 here). Snapshot at capture-OPEN (with the gain block), carried through capture-end + disarm header re-writes |
| 16 | 4 | **`snapStart` — ring index of record #0** (the snapshot-start marker) |
| 20 | 4 | recordCount |
| 24 | 4 | startTickMs |
| 28 | 4 | endTickMs |

- `[32..119]` = **v2 gain block** (absent in v1): `gainCount` u16 (=21,
  `TRACE_GAIN_COUNT`) + `TRACE_GAIN_VERSION` u16 (0) + 21 f32, per axis
  (Roll/Pitch/Yaw order) `R.Kp, R.Kd, R.Max, P.Kp (QKp), P.Ki, P.IntLim, P.Max`
  (`TRACE_GAIN_OFF_COUNT/DATA` offsets, FC `TraceSnapshotGains()`). Captured
  once at capture-open so a dump records the gains that actually flew, even if
  the GCS-locked gains shift on the ground before commit.
- `[120..127]` = pad (v2 header = `TRACE_HEADER_SIZE` 128).
- `[128..65535]` = rotating record region (16 B-aligned). Wrap is by-record:
  `write += 16; if (write >= TRACE_RING_SIZE) write = TRACE_DATA_BASE;` (no `/`
  or `%`). `TraceCount` caps at max records; once full, every overwrite advances
  `snapStart += 16` (wrapped), so the dump always knows where the snapshot began.

Max records drop accordingly: 64K ring `(65536-128)/16` = **4089** (was 4094),
F411 32K ring = **2040** (was 2046) — "probably minor" (Greg 2026-09-14).

Not in the RAM ring: nothing else — the capture is exactly header + records, and
that is what the flash copy and the dump stream carry. The on-board critic
trailer was REMOVED with the stimulus (2026-09-14); analysis is entirely the
GCS's job from the raw rows.

On **disarm** (both the `eLanded`-disarmed branch and the `eShutdown` →
`ePreflight` transition in `uavxarm-v3-gke.c`) → `TraceCommit()` writes ring
`[0 .. TRACE_HEADER_SIZE + recordCount*16)` to **`CAPTURE_FLASH_SECTOR` =
FLASH_Sector_10, `CAPTURE_FLASH_ADDR` = 0x80C0000** (top-of-image reserve,
sectors 10–11 free; image region already ends at 0x80C0000 so no linker change),
in a single `WriteBlockArmFlash`. Nothing is written to flash in the air.
Erase+program on disarm blocks ~seconds — safe there (motors stopped; same
exposure `RefreshConfig()` already has).

**Dump** (GCS `Dump` button → `MiscCommand.BB_DUMP` = miscBBDump → tag-54
`SendBBChunk` transport, unchanged): source priority = CCM ring if a snapshot
exists, else the committed flash copy; the stream is always TRACE_HEADER_SIZE B
header + chronological records (wrap-safe chunking by whole records, ≤128 B/pkt). **Fix:
`SendBBChunk` was only called in the non-`HIGH_RATE` branch of
`CheckTelemetry`, so the GCS never received dumps on the USB link — trace dump
adds `BBDataPending()/SendBBChunk(s)` to the `HIGH_RATE` branch.**
Legacy v1 dumps (32 B header, records at slot 32) still load — `parse_trace`
branches on version, so a v1 file from disk opens unchanged (no gains block,
pot code 0 → scale `None`).

**Flash lifecycle + dump availability (agreed 2026-09-01; critic talk removed
2026-09-14).** The dump facility is **retained** as the human waveform-viewing
path.
- `TraceCommit()` writes to the CAPTURE sector at **disarm only** when
  `pTraceType != eTraceNone` **and** `TraceCount > 0` (a capture actually ran).
  Default (`None`) never writes; enabling trace but never firing ch8 never writes.
- **Flash is NOT scrubbed on arm.** The sector holds the last
  disarm-with-capture indefinitely until a *new* disarm-with-capture overwrites
  it.
- **Dump source priority**: live CCM ring if `TraceCount > 0`, else the flash
  copy. After a power cycle the ring is empty, so a dump reads the flash copy
  **regardless of armed/disarmed** — the "good trace captured away from the GCS,
  dumped later on the bench" case works. **Accidental bench-arm is harmless**
  (arming alone neither populates the ring nor touches flash); the trace is only
  lost if you *fire a new capture (ch8 in flight) and disarm*, overwriting the
  sector. The GCS Dump button is **not** gated on armed state (`telem.c`
  `miscBBDump` → `StartBBChunkedDump()` runs unconditionally).
- **Flash endurance is a non-issue** at realistic rates: F4 spec 10k
  write/erase cycles on the dedicated CAPTURE sector → tens of years at dozens
  of flights/outing; power-loss mid-write is benign (non-boot-critical sector).
- Open sub-question (user, decide separately): keep flash persist at all vs
  RAM-ring-only now that the dump path is human-view only.

External-storage note (no action): the SpeedyBee F405 WING hardware DOES carry a
MicroSD slot (SPI3, PB3/PB4/PB5, declared in `speedybeef405wing.inc`), but
`eMemSel` is `{ false }` there and `spiflash.c` is SPI-NOR-flash-oriented only
(W25Q-style) — no MMC/SD SPI protocol or FAT filesystem exists in UAVX, and no
SPI3 CS is defined. Trace deliberately needs no external device (CCM ring → on-
disarm commit to internal CAPTURE sector → tag-54 dump). A future SD/FatFs port
for long multi-flight logs is a sizeable standalone task; SPI3 is uncontented
so the bus would be available.

`TraceTypes` enum (`trace.h`): `eTraceNone=0, eTraceRate=1, eTraceAttitude=2,

## Inflight Plant Identification (implemented 2026-09-14) — `identify.c`/`identify.h`
- **Passive, always-on, per-axis KF-RLS plant identifier** answering "can a model of the aircraft be approximated" — a scalar-Q KF whose equality with RLS+forgetting eliminates any fixed-window question. Model: per-axis first-order ARX `Rate[k+1] = a·Rate[k] + b·Out[k]` at the 500 Hz control rate; **never injects a stimulus, never gated on ch8, never writes `A[a].Out`** — it only reads the finalised `A[a].Out` (post-`RateGainScale`/`conditionOut`) and measured `Rate[a]` (gyro) and refines `(a,b)` via KF-RLS (`P0 = diag(0.1, 0.1)`, scalar-Q adaptive forgetting).
- **Excitation deadbands (locked):** update a sample only when `Abs(A[a].Out) > IDENTIFY_DEADBAND_OUT (0.1f)` AND `Abs(ΔRate) > IDENTIFY_DEADBAND_RATE (0.05f)` rad/s — a tight gate = fewer bad updates (safer than loose).
- **State machine** per axis (`IdentifyState`): `eIdleStep` (armed → wait first excited sample → `eTracking`), `eTracking` (start counting `n` — this is where the DC-gain cone starts tightening), `eConverged` (auto-hysteresis via `sigA/sigB < 0.01` → drops back to `eTracking` when Q re-opens); `IdentifyReset(idx a)` (= zero a single axis — **NOT wired at arming, design §5.3 says optional**; the Q keeps the filter adaptive and `IdentifyInit` restores the flash snapshot so previous flights' identification carries forward).
- **Flash snapshot reuses the CAPTURE sector** (mothballed trace owner): `CAPTURE_FLASH_SECTOR/ADDR`, 128 B image = magic `"IDEN"`(4) + version `1`(4) + f32 `dT`(8..11) + 3 axes×20 B from 12 (`a,b,sigA,sigB` f32 + `n` u32). `IdentifyInit()` (uavxarm-v3-gke.c ~177 boot + ~296 re-init, top-level init per design item 3) restores via `ReadBlockArmFlash` (all-0xFF unwritten sector fails magic → defaults); `IdentifyCommit()` gated on an `IdentifyDirty` flag (skip when no in-flight update this session — preserves the sector across disarm-without-flight) and called at BOTH disarm sites (~412 eLanded-disarmed and ~454 eShutdown→ePreflight). ## Mag Gating (implemented) — r??+
- `UseMag` config bit (`UseMagMask`) is the master switch: off = gyro-only yaw (use it while bench-debugging).
- Fusion auto-gated out ONLY in PassThru/ePIC (bare-metal) — `inertial.c` `MadgwickUpdate`: `F.NewMagValues && !F.MagnetometerFailure && !F.PassThru && State == eInFlight`.
- Deliberately NOT restricted to autonomous flight: a live calibrated mag anchors yaw in manual flight too.
- **Body-frame field convention = `(cos ψ, −sin ψ, 0)` at heading ψ, level** (physical NED body axes; 2026-09-18). Madgwick's magnetometer term expects this and tracks at every `pKpMag`; the twin showed the previous emu `(−sin, +cos, 0)` reflection tracks only at the near-zero default gain and diverges (−27.6° at `pKpMag=0.5`). **The emu fake mag is rotated by the TRUE attitude `EmuTrueQ`** (first row of the body-from-world DCM, horizontal field taken as due north — `emu.c` `DoEmulation`), NOT by a yaw-only accumulator; a level-only field fed Madgwick a correction that fought the true bank/pitch (suspect for the FW banked-turn yaw freeze). ## Lateral-Directional Mode Analysis (test_pid_sim.py, Aug 29)
- `analyze_lateral_modes(af_filename)` in `src/tests/test_pid_sim.py` adds the
  open-loop-screen blind spot the free-flight turbulence test cannot see:
  it linearizes the 4-state lateral-directional model (β, p, r, φ) and reports
  **Dutch-roll damping ζ + period**, **spiral T₁/₂** (or T-double when
  unstable), and roll-subsidence τ, per FW frame.
- Derivative set feeds 100% from the existing FW descriptor data: C_lβ via the
  shared `_effective_dihedral()` (extracted refactor of the free-flight block),
  N_β from `yaw_stability`, L_r from `dihedral_coeff`, damping as equivalent-
  LINEAR terms at `LIN_EQ_RATE = 0.25 rad/s` (the sim's quadratic damping
  needs an operating amplitude), fin Y_β / N_r from `rudder_area`+`rudder_arm`
  with `A_V_FIN = 2.5` fin lift-slope assumption. N_p = 0 (no such coupling in
  the sim). Gates: FAIL when DR ζ < `DR_ZETA_MIN` (0.05) or spiral unstable
  with T₁/₂ < `SPIRAL_T_DOUBLE_MIN` (8 s); wide-margin, screen-only — never
  feeds the tuning sims. Currently dormant for the whole fleet (ζ 0.25–0.49,
  all spirals stable).
- **Numerics trap**: Durand–Kerner iteration stalls to non-root fixed points
  when all four roots are real (the fleet default), and Python `**(1/3)`
  returns the complex principal root of a negative real (breaking Cardano).
  Solver is therefore the **closed-form Ferrari quartic** (`_quartic_roots`)
  with a sign-preserving `_cbrt`; validated fleet-wide `det(A−λI) ≤ 7e-12`.

## Coding Standards (classic C, real-time safe)
1. Pure classic C (C99/C11). No goto. Exactly 1 exit per function — return only on last line. No early returns.
2. No division operators (`/` or `%`) anywhere. Only exceptions: divisions that are inherent to the math and cannot be avoided (user ruling, 2026-08-31) — e.g. the critic-metric overshoot % (`peak/setpoint`) and dt-index scaling; follow existing precedent (`control.c:76` `1.0f/AttitudeCosine()`, `inertial.c:85` `Acc[Z]/AccMag` guarded). When a divisor is a **constant or a literal**, never divide by it — multiply by its inverse instead (`x / 100.0` is banned; use `x * 0.01f`, `x / 3` is banned; use `x * (1.0f/3.0f)`, and more `x / 2` is banned; use `x * 0.5f`). Division remains only where the divisor is a runtime value that cannot be precomputed (user ruling, 2026-09-01). No braces for single statements. Minimal, readable expressions.
3. Use `switch()` over deep if-else chains (3+ branches = switch). Encapsulate repetitive code. Cyclomatic complexity <10.
4. Preserve ALL code (and error handling) during refactoring. Comments: keep those that still reflect what the code does; DELETE comments that no longer reflect the code's function (stale comments mislead the next reader more than their absence). NEVER remove the main file-header comment block (copyright/licence/attribution header) from any file.
5. Bounds checking on ALL array accesses EXCEPT when loop bound ≤10 AND known at compile time (counter type irrelevant — `unsigned char`, `int`, `size_t` all fine). Use pattern: `if(index < SIZE) { access; } else { handle_error(); }`
6. *(intentionally skipped)*
7. No `malloc`/`free`. No pointer arithmetic (except same small-loop exemption as Rule 5). No casting between pointer types except to/from `void*`. Use static allocation or pool allocators. Zero sensitive memory after use.
8. Functions max 100 lines absolute (60-80 ideal). Exceeding requires refactoring into static helper functions.
9. Macros and constants = `UPPER_CASE`. Everything else: match existing code conventions; default to `snake_case` when no context exists. No leading underscores.
10. `#define` for compile-time constants (array sizes, switch cases, loop bounds, hardware addresses). `const` for type safety (floats, typed constants, debugger visibility). Enum constants are valid for switch case labels and `#define`-equivalent contexts. Rule of thumb: compile-time need = `#define`; type safety need = `const`.
- `//` comments are preferred. `/* */` also acceptable.
- No typedef for structs (except function pointers or opaque types). Let structs be visible.
- No magic numbers. Use named constants or enums. Only exceptions: 0, 1, NULL.
- Comments explain WHY, not WHAT. WHAT must be clear from code itself.
- Max line length: 80 characters.
- No assignments inside `if()` conditions.
- **ISRs must be minimal execution time.** Only simple state machines and flag-setting / queue-feeding belong in an ISR. Never run Kalman filters, trig/fp math, navigation, or EEPROM/flash writes from interrupt context: parse the packet/token, set a `...Received` flag, and let the main loop do the heavy processing when it polls the flag. Boundary: high-rate UART byte protocols (RC, GPS) may parse straightforward frame bytes in the ISR provided the completion handler only sets a flag.
11. **Real32 for physical quantities end-to-end.** Continuously-varying physical quantities (altitude, position, velocity, angles, rates, throttle, temperature, …) stay `real32` throughout the whole path: FC struct fields, wire packet encoding (`TxESCr32` / `UAVXPacketf32`), GCS models, and persisted `.af` config. Integer types are reserved for genuinely raw/quantised data (GPS int32 `1e7`, ADC/PWM/timer counts, enums, channel indices). This is not a preference — it eliminates silent truncation bugs in packet offsets and struct layouts (see item-7 latent offset bug: converting int16 fields to f32 without correcting the payload offsets corrupted every field after Velocity in the WP packet).

## Naming Conventions (schema — applies to new/edited code)
- **ParamTable targets/params**: param names referenced by `ParamTable` in `params.c`
  all start with lowercase `p` (e.g. `pArmingMode`, `pGyroLPFSel`, `pMaxAltHoldThrComp`).
- **Enum constants**: use lowerCamelCase **with a lowercase `e` prefix** (e.g. `eClassExplicit`,
  `eParamFloat`, `eCatFw`, `eFsRth`). The `e` is deliberate, not cosmetic: enum constants
  share the namespace with variables in C, so `classExplicit` is ambiguous (is it a value or
  a variable?) while `eClassExplicit` is unmistakable. Enum *type* names stay PascalCase
  (`ParamClass`, `AirframeCategory`). Apply to new and newly-edited enums.
